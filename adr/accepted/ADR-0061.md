# ADR-0061: Memory Subsystem Tuning

## Context

O laptop de desenvolvimento (16GB RAM, 8-core/12-thread) executava dois serviços
nocivos que sabotavam a performance de memória de forma sistemática:

1. **`memory-pressure-relief.service`**: executava `echo 3 > /proc/sys/vm/drop_caches`
   a cada 5 minutos, destruindo page cache, inode cache e dentry cache do kernel.
   Isso forçava re-leitura de disco para cada arquivo acessado, anulando o
   benefício do cache de 16GB de RAM.

2. **`swap-cleanup.service`**: executava `swapoff -a && swapon -a` a cada 30
   minutos quando RAM livre > 4GB. O `swapoff` força todo o conteúdo de swap de
   volta para RAM física, podendo causar OOM kill em cascata se a RAM real não
   comportar as páginas swap-in.

Ambos foram identificados como anti-patterns durante auditoria do subsistema
de memória em `modules/system/memory.nix`.

## Decision

### Remoções (anti-patterns)

| Serviço removido | Razão |
|------------------|-------|
| `memory-pressure-relief.service` + timer | `drop_caches` destrói cache do kernel; kernel gerencia cache melhor que script |
| `swap-cleanup.service` + timer | `swapoff -a` força swap-in massivo com risco de OOM |

### Recalibração de parâmetros kernel

| Parâmetro | Antes | Depois | Justificativa |
|-----------|-------|--------|---------------|
| `vm.dirty_ratio` | 20% (3.2GB) | 10% (1.6GB) | Evita I/O stalls por flush gigante |
| `vm.watermark_scale_factor` | 200 | 100 | Menos swap prematuro, menos CPU com compressão |
| `vm.min_free_kbytes` | 131072 (128MB) | 262144 (256MB) | Colchão maior para emergências |
| `vm.overcommit_memory` | 0 (heurístico) | 1 (always) | Node/Chrome/JVM/LLM alocam virtual enorme; OOMD protege |
| `vm.mglru.enabled` | — | 1 | Multi-Gen LRU: reclaim mais inteligente (kernel 6.1+) |

### Recalibração de slices cgroup v2

| Slice | Parâmetro | Antes | Depois |
|-------|-----------|-------|--------|
| Build | `MemoryMax` | 12G | 8G |
| ML | `MemoryMax` | 14G | 12G |

### Recalibração OOMD

| Parâmetro | Antes | Depois |
|-----------|-------|--------|
| `DefaultMemoryPressureLimit` | 60% | 80% |
| `DefaultMemoryPressureDurationSec` | 20s | 30s |

### Recalibração ZRAM

| Parâmetro | Antes | Depois |
|-----------|-------|--------|
| `memoryPercent` | 50% (8GB) | 30% (~5GB) |

### Higiene de processos

| Adição | Propósito |
|--------|-----------|
| `services.logind.killUserProcesses = true` | Mata todos processos do usuário no logout |
| `systemd.services."user@".serviceConfig.Subreaper = true` | systemd adota órfãos Node/Chrome |
| `reap-zombies.service` + timer (15min) | SIGCHLD para pais negligentes |
| `kernel.pid_max = 131072` | Pool de 128K PIDs (default 32K) |

### Inotify para desenvolvimento pesado

| Parâmetro | Antes | Depois |
|-----------|-------|--------|
| `fs.inotify.max_user_watches` | 1M | 2M |
| `fs.inotify.max_user_instances` | 1K | 2K |
| `fs.inotify.max_queued_events` | 32K | 64K |

### Ferramenta de auditoria

Script `scripts/config-audit-master.py` criado para cross-reference de opções
`kernelcore.*` entre módulos e host config, com validação tripla
(declarações ↔ referências ↔ host config). Integrado como módulo NixOS com
aliases (`audit`, `audit-check`, `audit-gap`, `audit-dead`) e autocomplete zsh/bash.

## Consequences

### Positivas
- ✅ Fim da destruição periódica de cache (ganho massivo de I/O)
- ✅ Fim do risco de OOM por swapoff forçado
- ✅ I/O stalls eliminados (flush 1.6GB em vez de 3.2GB)
- ✅ Menos swap prematuro (watermark 100 em vez de 200)
- ✅ Node/Chrome/LLM nunca falham malloc
- ✅ Zero zumbis e órfãos (killUserProcesses + Subreaper + reap-zombies)
- ✅ Visibilidade total da config com `audit` + autocomplete
- ✅ Contra-fact-check: 0 issues 🚨 HIGH após validação

### Negativas
- ⚠️ `overcommit_memory=1` delega toda proteção ao OOMD — requer OOMD bem configurado (80% threshold, nix-daemon+dbus protegidos)
- ⚠️ `max_user_watches=2M` pode consumir até ~2GB de kernel memory em cenário extremo

## Validation

- `scripts/config-audit-master.py --validate` → 0 🚨 HIGH, 5 💤 LOW (dead declarations em nvidia.prime)
- `nix-instantiate --parse` → OK em todos os arquivos modificados
- Sistema compilando sem erros após correção de `dns.` órfão em configuration.nix
